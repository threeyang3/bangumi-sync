## 发现与修复

本次先加入回归用例，复现六类问题，再修复：

1. 预览详情在共享 HTTP 队列等待时超时，之后仍会发出请求。将请求级过期/关闭检查传入 API 调度与重试边界，过期的未发送请求直接跳过；已发送请求仍占名额直到实际结束。
2. 清除或替换 manager 的取消 signal 会使旧队列请求复活。每个请求及其重试捕获创建时的检查器，manager 检查器绑定具体 signal；先前独立后台请求也不会误受新操作取消影响。
3. 自动同步入口漏掉提交后的批量关联补全。与手动导入和预览执行一致，在提交后调用统一批量补链服务。
4. 提交后补链期间取消仍报告成功。三个批次入口在补链后重新判断取消，保留已提交文件，终态显示取消，不重新生成 pending journal 或提供失效回滚。
5. Obsidian requestUrl 默认 throw 行为使 429/5xx 无法到达状态码重试分支。普通 API 请求显式 throw=false，保留 1/2/4 秒退避及最多四次请求；401 不重试。
6. 单 worker 同步把共享上限永久降为 1。同步及预览会话改为持有临时预算，成功、失败、关闭后释放；释放遵循最新基础设置，不能恢复过时设置。测试覆盖重复释放及操作中基础设置变化。
